# Current limitations

Lapui is an early prototype. It supports one application document, a partial dynamic DOM and text-form bridge, CSS selector queries through Blitz, `classList`, node creation/insertion/removal and sibling traversal, inline CSS property mutation/readback, bubbling listeners, semantic control snapshots (including associated labels and selected form state), basic activation/fill operations, registered Rust read/write actions and bounded background operations, and HTTP, WebSocket, and EventSource examples. Vue 3 and React DOM 19.2.0 bundles mount against the Blitz-backed DOM. React tests controlled input, effects, delegated events, list/conditional-content updates and an asynchronous Rust action through the AI channel. Live nodes keep canonical wrapper identity across detach/reinsert. The UI fills the window viewport and has pointer styles for its surface and button.

P1–P3 are not complete. Parley complex-script line breaking is enabled and a narrow Chinese paragraph layout test passes. A synthetic Blitz IME composition/commit test updates a focused input and dispatches one DOM `input` event; Windows IME candidate-window placement, caret geometry, selection replacement, and actual desktop input remain unverified. Form support covers text-like value reads/writes, reflected `disabled`, checkbox/radio checked state and explicit AI `lapui.check`, plus basic `input`/`change` dispatch. Programmatic focus, `activeElement`, focus events, keyboard fields/default cancellation, and Tab/Shift+Tab traversal have tests. Checkbox/radio click defaults, cancel rollback, labels, form-scoped radio selection, disabled-fieldset/readonly input gating, Space/Enter activation, and radio arrow navigation have focused native-event/AI regressions; see [forms](forms.md). Full HTML validation, selection, submit/reset/navigation, rich widget behavior, platform IME, and complete event semantics remain unsupported. `DocumentFragment` is currently backed by a detached placeholder element and its `childNodes` is a snapshot array; live collections and native node classes are not implemented. `innerHTML` uses Blitz's fragment parser and a limited HTML serializer; it does not execute inserted scripts and is intended for trusted application markup. Selector behavior needs a broader compatibility suite. Semantic references are document-scoped and include a versioned node ID; external control requests reject stale documents and detached targets. Fetch supports absolute HTTP(S), an explicit Rust HTTP document base, app-root-relative local GETs, buffered single-consumption text/JSON responses and cloning, basic iterable Headers, AbortController/timeout cancellation, and bounded concurrency/input/body size. WebSocket and EventSource have basic text/binary, reconnect, and close handling; several browser features and conformance tests are missing. Browser-complete async/defer scheduling, streaming/binary fetch bodies, full Web API compatibility, broader framework/component compatibility, state-preserving HMR, external AI adapters, and full tracing remain outstanding. Relative CSS/image/font resources and ordered classic scripts work for local HTML, restricted to files within its app directory.

Local ES modules now support static/dynamic imports, re-exports, cycles, shared module identity, `import.meta.url`, and top-level await. They use canonical file URLs and the app-directory boundary. Bare package imports, import maps/attributes, remote modules, and complete browser scheduling remain unsupported. Script, timer and supported dispatch errors are available through a bounded `lapui.diagnostics()` buffer; this is not a complete JavaScript debugger or global unhandled-rejection monitor.

Windows release builds and Rust tests pass. Automated layout tests cover viewport resize and cursor selection; bridge tests cover dynamic nodes, selectors, form filling, control semantics, batching, and event bubbling. Network integration tests use local HTTP, SSE, and WebSocket servers. Local resource/module tests reject paths outside the app root and malformed or oversized modules. CPU offscreen output and actual window/TCP paths have been checked; physical input and window visual fidelity still need platform verification. The React window and TCP activation path passed under WSLg/X11; Wayland startup failed in that environment. Physical input and other Linux desktops remain unverified.

The current Windows default release with CPU drawing, PNG support, native reload and CJK line-break data is 29,792,256 bytes (28.41 MiB). A previous GPU-only build without CJK data was 23,732,736 bytes (22.63 MiB); these builds differ in renderer capabilities as well as text data. A five-second sample of the previous GPU-backed embedded counter process used 608,256,000 private bytes (580.08 MiB) and 286,941,184 working-set bytes (273.65 MiB). That GPU sample remains far above the initial 80 MiB aspiration. The new default CPU drawing path produced a five-second sample of 10,297,344 private bytes (9.82 MiB) and 32,112,640 working-set bytes (30.63 MiB); see [rendering](rendering.md). Neither sample establishes long-run memory behavior. An older plain Blitz baseline used similar private memory to the earlier Lapui build; renderer/driver allocation still needs investigation. These are preliminary single-machine process samples, not startup or steady-state benchmarks; GPU memory and frame timings were not measured. The release module and React examples have passed window-process tests through the actual TCP controls/activate/observe/diagnostics path, without a physical-input or visual-fidelity claim. Rust host actions and an in-memory file tool additionally cover scoped action retirement, bounded discovery, invocation-time availability, schema validation, transactional state, pagination, entity-version conflicts, preserved human drafts, bounded background operations and finite action traces; see [Rust host actions](host-actions.md). Resumable application change subscriptions now cover state deltas, action metadata, operation summaries and explicit host events; see [changes](changes.md). DOM/control streams, durable job recovery, generic entity projections and renderer frame tracking remain outstanding.

Function-based timers and queueMicrotask are now supported with bounded native delivery and resumed Promise job checkpoints; see [Task scheduling](scheduling.md). Browser-complete scheduling and frame timing remain outstanding.

The default CPU path has an offscreen PNG API/CLI and a CSS pixel/resize regression. Current file-tool pixels have been visually inspected, including Chinese text; this is not a physical desktop-input test. Complete CSS filter support and renderer equivalence remain unverified.

Canonical wrappers use weak caching. A connected document retains its wrappers and listeners; retaining any detached node, its `style`, or its `classList` retains that subtree for reinsertion. Unreachable detached trees and listener cycles are collected at a document checkpoint, with native nodes released through Blitz's mutator. Regression tests cover 1,000 create/remove cycles, fragments/clones/child replacement, and 50 layout/remove cycles with stale-handle rejection. Manual and file-watched full reload have regression coverage; this is not a long-run memory or pause-time benchmark. Broader native-resource profiling remains unfinished.

Cooperative JS execution deadlines and a managed-heap cap now have runaway-callback/startup and reload-recovery coverage. Suspension preserves structured read access, but skips JS cleanup and does not undo effects. Native calls cannot be preempted, and heap exhaustion can interfere with error reporting; see [scheduling](scheduling.md). These limits do not establish frame latency or a security sandbox.
